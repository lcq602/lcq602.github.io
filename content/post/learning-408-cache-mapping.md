备考 408 的时候，我发现组成原理里最容易“以为自己会了、真题一做就错”的，就是 Cache。三种映射方式的名字都背得下来，可题目一给具体地址，问命中几次，脑子就乱了。这周我索性把一块 8KB 的 Cache 从头算了一遍，顺便写了个 C 程序验证，算是把这个点彻底钉死了。

## 先把问题摆清楚：Cache 到底在解决什么

CPU 很快，主存很慢。Cache 就是夹在中间的一层小而快的存储，容量只有主存的零头，却要装下程序最常访问的那部分数据。能不能命中，取决于一个核心问题：**主存里的一个块，到了 Cache 里能放在哪几行？**

答案有三种，对应三种映射方式：

- **直接映射**：一个主存块只能去唯一的一行。快，但容易“撞车”。
- **全相联映射**：一个主存块可以去任意一行。灵活，但查找要全表比对，贵。
- **组相联映射**：折中。Cache 先分小组，一个主存块只能去某个组，但在组内任意一行都行。n 路组相联就是每组 n 行。

考试最爱考的，就是给定 Cache 大小和主存大小，让你画出 32 位地址里**标记（Tag）、组号（Index）、块内地址（Offset）**各占几位。

## 一道题算到底：8KB Cache，64B 块，主存 4GB

设定：Cache 容量 8KB，块大小 64B，主存 4GB，所以地址是 32 位。Cache 一共有 8KB / 64B = **128 行**。

块内地址固定是 log₂64 = **6 位**，三种方式的区别只在剩下的 26 位怎么分：

| 映射方式 | 组数 | 组号位数 | 标记位数 |
| --- | --- | --- | --- |
| 直接映射 | 128 行 | 7 位 | 32 − 6 − 7 = **19 位** |
| 4 路组相联 | 128 / 4 = 32 组 | 5 位 | 32 − 6 − 5 = **21 位** |
| 全相联 | 1 组 | 0 位 | 32 − 6 = **26 位** |

我一开始总记混组号和标记的位数，画个地址图就清楚了：从低位往高位，块内地址 6 位，组号紧挨着它，剩下的高位全是标记。直接映射行数最多，组号最长，标记最短；全相联没有组号，标记最长。这个规律不用背，推一遍就记住了。

## 完整算例：同一串访问，三种映射三种结果

取一块访问序列（单位是主存块号）：

```text
0, 1, 2, 128, 0, 129, 1, 130, 2, 131, 3, 4, 5
```

这串数字是我故意挑的：块 0 和块 128 在直接映射下会抢同一行（128 mod 128 = 0），块 1 和 129 抢第 1 行，块 2 和 130 抢第 2 行。逐个模拟的结果如下：

**直接映射（128 行）：命中 0 次，命中率 0%**

块 0 刚装进第 0 行，块 128 就来把它挤走；块 0 再来，又是缺失。来回拉锯，13 次访问全是缺失。这就是课本上说的**冲突缺失**导致的“抖动”（thrashing）：Cache 明明没满，命中率却是零。

**4 路组相联（32 组）：命中 3 次，命中率 23.1%**

块 0 和块 128 都分到第 0 组（0 mod 32 = 0，128 mod 32 = 0），但组里有 4 行，两个块可以共存。第二次访问块 0、块 1、块 2 时全部命中。3 次命中都来自第二次访问。

**全相联（LRU 替换）：命中 3 次，命中率 23.1%**

这个序列里全相联和 4 路组相联结果相同，因为访问的块总数只有 9 个，远没到需要替换的地步。区别要到访问规模超过 Cache 容量、开始淘汰时才显现。

这个算例给我的教训很实在：**Cache 的性能不只看容量，更看映射方式和访问模式合不合拍。** 直接映射在顺序访问时表现很好，一遇到跨步 128 块的交替访问就全军覆没。真题里那种“问命中率”的题，本质上就是让你手算一遍这个过程。

## 写一段 C 代码，把手算变成机算

手算 13 次访问还行，真题给 20 次就容易数错。我写了个直接映射的小模拟器，跑出来的结果和上面手算完全一致：

```c
#include <stdio.h>
#define LINES 128          /* Cache 8KB / 块 64B = 128 行 */
int main(void) {
    int seq[] = {0, 1, 2, 128, 0, 129, 1, 130, 2, 131, 3, 4, 5};
    int n = sizeof(seq) / sizeof(seq[0]);
    int tag[LINES], valid[LINES] = {0};
    int hits = 0;
    for (int i = 0; i < n; i++) {
        int line = seq[i] % LINES;   /* 组号 = 块号 mod 行数 */
        int t = seq[i] / LINES;      /* 标记 = 块号 / 行数 */
        if (valid[line] && tag[line] == t) {
            hits++;
            printf("块 %3d -> 行 %3d  HIT\n", seq[i], line);
        } else {
            valid[line] = 1; tag[line] = t;
            printf("块 %3d -> 行 %3d  MISS\n", seq[i], line);
        }
    }
    printf("命中 %d/%d = %.1f%%\n", hits, n, 100.0 * hits / n);
    return 0;
}
```

编译运行后输出 13 行 MISS，最后 `命中 0/13 = 0.0%`。把 `LINES` 改成组相联的逻辑、再加一个 LRU 队列，就能模拟另外两种方式——这个可以当作课后练习，核心就两行：组号取模、标记取整除。

## 命中率之外：平均访问时间怎么算

命中率本身不是目的，目的是算平均访问时间。公式只有一个，考试年年考：

```text
T(平均) = T(命中) + (1 − 命中率) × T(缺失代价)
```

代入一组典型数字：Cache 命中 1 个周期，缺失去主存要 100 个周期，命中率 95%，则平均访问时间 = 1 + 0.05 × 100 = **6 个周期**。命中率只掉了 5 个百分点，平均时间却变成命中时间的 6 倍——这就是为什么所有优化都围着命中率转。

顺带记一个易错点：**写策略（写回法 vs 写直达法）和替换算法（LRU、FIFO、随机）不影响地址划分**，它们只在缺失和写操作时才起作用。做题时先把 Tag/Index/Offset 分清楚，再去想替换和写策略，别一上来就混在一起。

## 我给自己的检查清单

下次再遇到 Cache 大题，我会按这个顺序做：

1. 先算行数 = Cache 容量 / 块大小，块内地址 = log₂块大小。
2. 按映射方式算组数，再分 Tag 和 Index 的位数。
3. 把访问序列换算成块号，逐个查组、比标记，命中画勾、缺失画叉。
4. 命中率算完如果题目问平均时间，套一次公式，别直接拿命中率当答案。

Cache 这章的题看着吓人，其实全是按部就班的算术。真正会丢分的地方，是组号位数算错一位，或者把块号当成了字节地址——我第一次做就栽在后者上。把地址先除以块大小换成块号，这一步写在草稿纸最上面，基本就不会再错了。
