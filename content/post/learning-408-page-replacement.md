上周算完 Cache 映射，我一直有个念头挥不去：Cache 是硬件在管，换进来换出去全自动；可到了虚拟内存这一层，页面换进换出是操作系统软件在管，策略就得我们自己选了。同样是“满了，淘汰谁”，FIFO、LRU、Clock、OPT 四种算法给出的答案能差出一倍。今天我拿操作系统里最经典的一串页面访问，把四种算法逐个手算了一遍，还写了个 C 程序验算。

## 先把问题摆清楚：缺页了，淘汰谁

程序访问的地址空间被分成等大的**页**，内存被分成等大的**页框**。CPU 要访问某页，发现它不在内存里，就触发**缺页中断**，操作系统从外存把这一页调进来。如果这时内存已经满了，就必须先挑一页换出去，腾出位置。

置换算法要回答的只有一个问题：**换出哪一页，未来付出的代价最小？** 衡量标准也很直接——给定一串页面访问序列，统计**缺页次数**，越少越好。缺页率 = 缺页次数 / 访问总次数。

这道题在 408 里年年换皮出现：给一个访问序列和页框数，问某种算法缺页几次；或者反过来，问哪种算法缺页最少。手算的套路只有一个：维护一张“内存里现在有哪几页”的表，逐个访问，命中画勾、缺失画叉，缺失时按规则淘汰。

## 完整算例：同一串访问，四种算法四种结果

取操作系统教材里最经典的一串访问（页号），共 20 次：

```text
7, 0, 1, 2, 0, 3, 0, 4, 2, 3, 0, 3, 2, 1, 2, 0, 1, 7, 0, 1
```

分配 **3 个页框**。四种算法的结果，我先把结论放在这里，过程在下面：

| 算法 | 缺页次数 | 缺页率 | 备注 |
| --- | --- | --- | --- |
| FIFO（先进先出） | 15 | 75% | 只看装入时间 |
| Clock（时钟） | 14 | 70% | LRU 的廉价近似 |
| LRU（最近最久未用） | 12 | 60% | 实际系统的主流选择 |
| OPT（最佳置换） | 9 | 45% | 理论下界，实现不了 |

### FIFO：先进来的先出去

FIFO 只记一件事：每页是什么时候装进内存的。缺页时淘汰装入时间最早的那一页。逐步骤如下（方框里是 3 个页框当时的内容）：

| 访问 | 7 | 0 | 1 | 2 | 0 | 3 | 0 | 4 | 2 | 3 | 0 | 3 | 2 | 1 | 2 | 0 | 1 | 7 | 0 | 1 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 结果 | 缺 | 缺 | 缺 | 缺 | 命 | 缺 | 缺 | 缺 | 缺 | 缺 | 缺 | 命 | 命 | 缺 | 缺 | 命 | 命 | 缺 | 缺 | 缺 |

15 次缺页，5 次命中。访问第 4 个页（页 2）时，淘汰的是最先装入的页 7——哪怕页 7 之后还会再被访问。FIFO 的毛病就在这儿：**它只认“来的早晚”，不认“用得勤不勤”**。页 0 在第 2 步刚装进来，第 5 步就被访问了一次，可第 6 步来页 3 时，页 0 还是因为“来得早”被淘汰，紧接着第 7 步访问页 0 又缺页。这种刚换出去马上又要用的情况，在 FIFO 里比比皆是。

### LRU：淘汰最久没被碰过的那一页

LRU 的直觉是“最近用过的，接下来还可能用”——这就是**局部性原理**。实现上要给每页记一个“上次访问时刻”，缺页时淘汰时刻最久远的那一页。同一串访问，LRU 只缺页 12 次，比 FIFO 少 3 次。关键差别出现在第 7 步：访问页 0 时，LRU 淘汰的是页 1（它从第 3 步之后就没被碰过），而不是 FIFO 淘汰的页 0 自己。这一换，后面第 7 步的页 0 直接命中，省下一次缺页。

代价是 LRU 需要硬件或软件维护访问时间戳，开销比 FIFO 大。真实系统里纯 LRU 很少直接实现，更多用近似算法代替——这就是 Clock 登场的理由。

### Clock：给每页一个“访问位”，指针转圈找替罪羊

Clock 也叫“第二次机会”算法：每页多一个访问位（引用位），被访问过就置 1；再加一个像时钟一样的指针。缺页时指针顺时针扫：遇到访问位是 1 的页，就把它清 0、放过一次，指针继续走；遇到访问位是 0 的页，就淘汰它。

这串访问用 Clock 算下来是 14 次缺页，介于 FIFO 和 LRU 之间。Clock 的妙处在于开销极小——只需要一个比特位和一个指针，效果却接近 LRU。Linux 里的页面回收用的就是 Clock 的改进版。考试如果问“实际系统常用什么”，答案往往是它，而不是理论上最优的 LRU。

### OPT：永远淘汰未来最久才用到的页

最佳置换算法 OPT 的规则反过来：缺页时，看每页未来什么时候再被用到，淘汰那个**最久以后才用到、或者再也不用**的页。同一串访问，OPT 只要 9 次缺页，是这四种算法的下限。

但 OPT 有个致命问题：**它要预知未来**。操作系统做决策的那一刻，并不知道程序接下来要访问什么页。所以 OPT 在真实系统里实现不了，它存在的意义是当标尺——任何实际算法的缺页次数都不可能比它更少。408 考它，考的就是你能不能按“向未来看”这个规则手算，而不是考它实不实用。

## 反直觉的坑：Belady 异常——内存给多了，缺页反而多了

算到这里，我以为“页框越多，缺页越少”是天经地义。直到我算了下面这串访问：

```text
1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5
```

FIFO 算法，3 个页框缺页 9 次；改成 **4 个页框，缺页变成 10 次**。多给一个页框，缺页反而多了一次。这就是 **Belady 异常**，以发现者 Belady 的名字命名。

原因藏在 FIFO 的淘汰顺序里：多一个页框改变了每一页被淘汰的时机，页 3、页 4 在 4 帧的情况下反而比在 3 帧时更早被换出去，后面再访问时就多出缺页。直觉上“资源越多越好”，在这里失效了。

这条异常不是所有算法都有。LRU 就没有这个毛病：同一串访问，LRU 3 帧缺页 10 次，4 帧降到 8 次，页框越多缺页单调不增。满足这个性质的算法叫**栈算法**（stack algorithm），OPT 和 LRU 都是，FIFO 不是。考试很爱在这里设陷阱：问“下列哪种算法可能出现 Belady 异常”，答案是 FIFO；问“哪种一定不会”，答案是 LRU 和 OPT。记住这个对比，比背定义管用。

## 写一段 C 代码，把四种算法一次算完

20 次访问手算还能应付，真题给 30 次就容易数错。我写了一个三合一的小模拟器，FIFO、LRU、OPT 各一个函数，主函数里跑上面两串访问，输出和手算完全一致：

```c
#include <stdio.h>
#define MAXF 8

/* FIFO：按装入顺序淘汰最先进入的那一页 */
int fifo(int *seq, int n, int frames) {
    int f[MAXF], head = 0, cnt = 0, faults = 0;
    for (int i = 0; i < frames; i++) f[i] = -1;
    for (int i = 0; i < n; i++) {
        int hit = 0;
        for (int j = 0; j < cnt; j++) if (f[j] == seq[i]) hit = 1;
        if (hit) continue;
        faults++;
        if (cnt < frames) f[cnt++] = seq[i];
        else { f[head] = seq[i]; head = (head + 1) % frames; }
    }
    return faults;
}

/* LRU：淘汰最久没被访问的那一页，last[] 记录每页上次访问时刻 */
int lru(int *seq, int n, int frames) {
    int f[MAXF], last[MAXF], cnt = 0, faults = 0, t = 0;
    for (int i = 0; i < frames; i++) { f[i] = -1; last[i] = -1; }
    for (int i = 0; i < n; i++) {
        int hit = -1;
        for (int j = 0; j < cnt; j++) if (f[j] == seq[i]) hit = j;
        if (hit >= 0) { last[hit] = ++t; continue; }
        faults++;
        if (cnt < frames) { f[cnt] = seq[i]; last[cnt] = ++t; cnt++; continue; }
        int victim = 0;
        for (int j = 1; j < frames; j++)
            if (last[j] < last[victim]) victim = j;
        f[victim] = seq[i]; last[victim] = ++t;
    }
    return faults;
}

/* OPT：淘汰未来最久才用到的那一页（理论下界，无法真正实现） */
int opt(int *seq, int n, int frames) {
    int f[MAXF], cnt = 0, faults = 0;
    for (int i = 0; i < frames; i++) f[i] = -1;
    for (int i = 0; i < n; i++) {
        int hit = 0;
        for (int j = 0; j < cnt; j++) if (f[j] == seq[i]) hit = 1;
        if (hit) continue;
        faults++;
        if (cnt < frames) { f[cnt++] = seq[i]; continue; }
        int victim = 0, farthest = -1;
        for (int j = 0; j < frames; j++) {
            int next = n + 1;   /* 之后再也不出现，视为无穷远 */
            for (int k = i + 1; k < n; k++)
                if (seq[k] == f[j]) { next = k; break; }
            if (next > farthest) { farthest = next; victim = j; }
        }
        f[victim] = seq[i];
    }
    return faults;
}

int main(void) {
    int seq[] = {7,0,1,2,0,3,0,4,2,3,0,3,2,1,2,0,1,7,0,1};
    int n = sizeof(seq) / sizeof(seq[0]);
    printf("3帧: FIFO=%d LRU=%d OPT=%d\n",
           fifo(seq, n, 3), lru(seq, n, 3), opt(seq, n, 3));
    printf("4帧: FIFO=%d LRU=%d OPT=%d\n",
           fifo(seq, n, 4), lru(seq, n, 4), opt(seq, n, 4));
    int bel[] = {1,2,3,4,1,2,5,1,2,3,4,5};
    int m = sizeof(bel) / sizeof(bel[0]);
    printf("Belady: FIFO 3帧=%d, FIFO 4帧=%d\n",
           fifo(bel, m, 3), fifo(bel, m, 4));
    return 0;
}
```

编译运行，输出是：

```text
3帧: FIFO=15 LRU=12 OPT=9
4帧: FIFO=10 LRU=8 OPT=8
Belady: FIFO 3帧=9, FIFO 4帧=10
```

和前面手算的数字逐个对得上。Clock 的实现可以当作课后练习：在 FIFO 的 `head` 指针之外，给每页加一个 `ref[]` 访问位，命中时把对应位置 1，淘汰时指针遇到 1 就清 0 跳过、遇到 0 才换出——核心逻辑十几行就能写完。

## 缺页率之外：有效访问时间与抖动

缺页次数本身不是目的，目的是算它对程序速度的影响。公式和 Cache 那篇的平均访问时间是同一个思路：

```text
有效访问时间 EAT = (1 − p) × 内存访问时间 + p × 缺页处理时间
```

代入一组典型数字：内存访问 200ns，一次缺页处理（换出旧页、读入新页、更新页表）要 8ms，缺页率 p = 1/1000，则 EAT ≈ **8.2μs**。命中一次只要 200ns，平均下来却慢了 40 多倍——缺页处理是内存访问的 4 万倍，哪怕缺页率只有千分之一，也能把平均时间拖垮。这就是为什么所有置换算法都在拼那几个百分点的缺页率。

还有一个比缺页率更严重的概念：**抖动（thrashing）**。当进程的工作集——也就是它在一段时间内真正需要的那组页面——超过了分给它的页框数，系统会陷入“刚换进来又换出去”的死循环，CPU 大部分时间都在等换页，真正干活的时间反而没多少。治抖动的办法不是换更聪明的算法，而是**控制进程的并发度**，或者给抖动的进程多分配页框，让它的工作集能装得下。

最后记一个常考的细化版：**改进型 Clock**。普通 Clock 只看访问位，但淘汰干净页和脏页的代价不一样——脏页换出前要先写回外存。改进型 Clock 给每页再加一个修改位，把页面分成 (访问位, 修改位) 四类：(0,0)、(0,1)、(1,0)、(1,1)，按这个顺序优先淘汰。考试问到“减少写回次数”时，答案往往就是它。

## 我给自己的检查清单

下次再遇到页面置换大题，我会按这个顺序做：

1. 先把访问序列抄下来，数清次数，页框数写在最上面。
2. FIFO：维护一个队列头指针，装入顺序淘汰；命中不改变任何顺序。
3. LRU：给每页记上次访问时刻，缺页时淘汰时刻最小的；命中要更新时刻，别忘了。
4. OPT：每次缺页都往未来看，淘汰下次用得最晚的那一页；再也不用的页优先级最高。
5. Clock：访问位置 1，指针遇到 1 清 0 跳过、遇到 0 淘汰。
6. 算完缺页次数先除以总次数得缺页率，题目问有效访问时间再套一次公式。
7. 看到“页框增多缺页反而增多”，先想到 Belady 异常，再想这是不是 FIFO。

Cache 那篇让我明白，命中率拼的是映射方式和访问模式合不合拍；这一篇让我明白，缺页率拼的是淘汰策略和程序的局部性合不合拍。两章合起来，存储层次的题基本就剩一个套路：**先把结构画出来，再把访问序列一格一格走过去**。数字不会骗人，手算一遍，比背十遍定义都牢。
